# Winamp 皮肤窗口的原生吸附与分离

## 原因

旧实现绕开了 TTPlayer 的原生拖动流程：主窗口按下时，将所有可见的播放列表、均衡器加入 `attached`，不检查窗口边界是否连接。拖动时先 `SetWindowPos` 主窗，再逐个移动附窗，既没有磁性吸附，也无法在分离后停止跟随；窗口更新顺序还可能产生不同步的观感。

## 原版依据

依据本地 `reverse/decompiled/TTPlayer.exe.pseudo.c`，不是 Winamp 自身的窗口吸附策略：

| 原版函数 | 本次采用的行为 |
| --- | --- |
| `0046EAAC`、`0046EB64`、`0046EB28` | 客户区按下建立捕获；每条鼠标移动消息同步计算当前位置；释放时结束拖动。 |
| `0040BFD7` | 判断窗口边界相等且另一轴区间相交；包括相邻边接触及重叠窗口的同侧边对齐。 |
| `0047075B` | 主窗口拖动时建立相连窗口组，包括通过其他附窗间接连接的窗口；单独拖动附窗可以分离。 |
| `0044F804`、`0041094D`、`004114FE`、`0040BEDD` | 对工作区及注册窗口计算最近边界修正；默认 10 像素，包括恰好 10 像素的边界。 |
| `004708B4` | 对主窗和连接组统一应用修正，通过 `BeginDeferWindowPos`／`EndDeferWindowPos` 批量移动；吸附距离为零时不带动附窗。 |
| `004709A2` | 缩放时仅修正活动边，不平移对边。 |

## 实现

DLL 继续负责 WSZ 读取、绘制、窗口区域、按钮与标题栏命中。标题栏拖动和播放列表缩放通过 `TtpSkinHost.drag` 同步调用宿主已有的 `BeginSkinBackgroundDrag`、`ContinueSkinBackgroundDrag`、`EndSkinMouseCapture`。这使原生与 Winamp 皮肤共享一套连接判断、工作区吸附及窗口组更新逻辑，原生歌词窗口也能参与。

- 不再保留 DLL 的“所有可见附窗跟随”列表。
- 不投递移动命令，也不依赖 100 ms 绘制计时器移动附窗。
- 吸附距离和开关直接使用“常规”中的现有设置。
- 缩放由 DLL 提供最小尺寸，避免误用作为歌词／对话框后备的原生皮肤尺寸。
- 拖动开始只捕获一次鼠标；释放、取消、捕获丢失、换肤及解绑均清理双方状态，避免同步 `WM_CAPTURECHANGED` 造成重入残留。

`drag` 是 ABI v1 的可选尾部扩展，按 `size` 协商，不改变已有字段。新 DLL 可安全读取旧长度的宿主接口；旧 EXE 没有此回调时只能独立移动单窗。**使用完整修复需要同时更新 EXE 和 DLL。** 普通版和 XP／Win7 版仍共享一份 DLL；播放命令继续使用原有异步命令接口。

## 本地验证

测试位于 `rebuild/tests/waskin`，不进入发布包或 Actions：

- 主窗、均衡器、播放列表传递连接；每条移动消息返回前三窗已到达目标位置。
- 附窗独立分离，分离后不跟随，重新吸附后再次跟随。
- 原生歌词参与连接组，同侧对齐的重叠窗口联动。
- 10／11 像素边界、自定义 22 像素距离、关闭吸附。
- 折叠后的实际窗口边界、列表最小尺寸和缩放吸附。
- 松手、取消、捕获丢失及拖动中换肤。
- 实际 `SendInput` 鼠标拖动，并检查捕获、主窗和附窗坐标。
- 旧长度 ABI 的缓冲区末尾放置保护页，检查插件没有越界读取新增回调。

旧系统导入审计与当前 Windows 上的两版宿主集成验证不替代实际 XP／Win7 系统运行验证。
