## 新视觉效果

旧插件有多处独立的 `0..4` 范围限制：

- `Skin::ContentState` 和 `Modern::ContentState` 会拒绝宿主新菜单设置的类型。
- WSZ 和 WAL 的 provider 菜单都只列出五种类型。
- WSZ 的布局版本 2、WAL 的布局版本 3 载入器拒绝类型 5、6，保存后重新选择皮肤会丢失布局状态。
- 宿主 `TTP_SKIN_CONTENT_FULLSCREEN` 入口仍只接受 `<=4`，即使显示出新效果也无法进入相应全屏。

现在由插件中的 `visualEffectNames` 统一菜单和校验范围，新增命令 715、716。WSZ 与 WAL 的现有布局格式保持不变，扩展合法类型值；非法类型 7 及更大值仍被拒绝。WAL 后备 WSZ 窗口的布局也同步支持。

公开 SDK 只同步了宿主的视觉类型注释，结构体、回调和命令编号没有新增或重排。两边 SDK 头文件内容一致。新效果由宿主现有渲染器完成，插件没有复制音频分析或新增 Wasabi 依赖。

## 搜索焦点

WSZ 隐藏了宿主的原生列表子控件，自行在播放列表 HWND 绘制并接收键盘；WAL 还允许在主 HWND 中显示列表。宿主新增的搜索结束处理直接 `SetFocus(playlist_track_control_)`，会将焦点交给隐藏控件，WAL 同时可能被激活到另一份后备列表。

修复记录搜索前的列表窗口，搜索关闭后激活该窗口：插件接管的列表将焦点给对应 HWND，原生列表仍给 Files。F3 的恢复路径采用相同规则。在搜索框输入及进度处理期间继续保留查询框焦点，选中项和宿主当前行不重新计算，Enter 仍使用最后匹配的当前行。

修复前 WSZ / HeadAMP 的回归均在“关闭搜索后焦点应回到实际插件列表”断言失败；修复后两者及原生搜索高亮测试均通过。
