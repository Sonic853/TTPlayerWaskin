## 向外拖出歌曲

旧 DLL 的鼠标捕获逻辑只计算内部重排位置。离开播放列表后清掉了插入行，但未开始 OLE 拖放，
因此外部程序收不到 `IDataObject`，并非文件路径编码本身导致。

现在跨过拖动阈值并离开窗口后，DLL 清理内部拖动和捕获，再排队发送 `TTP_SKIN_DRAG_SELECTION`。
宿主检查“允许拖放”、窗口和左键状态，调用原有 `BeginPlaylistOleDrag`。该命令异步处理，
`DoDragDrop` 的消息循环开始时 DLL 不在调用栈上，允许期间正常处理界面消息及换肤。

数据继续使用原生 `PlaylistDragDataObject`：本地文件为 Unicode `CF_HDROP` 和 Shell IDList，
网络项使用已有 URL 格式。文件多选顺序和源曲目身份由宿主管理，COPY／LINK 保留曲目，
MOVE 按已导出的身份删除列表条目，Escape 取消保留原列表。拖动图像的源 HWND 改为可见的
提供者列表窗口，避免向已隐藏的原生 ListView 请求图像。内部重排／复制也遵守“允许拖放”。

本次没有为压缩包内部的虚拟歌曲创建可拖出的临时文件；文件接收程序仍需支持所接收的
真实音频格式，网络地址则需支持 URL 拖放。

## 验证

本地 `rebuild/tests/waskin/adaptation_host_tests.inc` 覆盖实际提供者自动宽度、

检查中文／空格完整路径、文件顺序及可读取的 WAV 文件头，并分别验证 COPY、MOVE、Escape。
已有拖入测试继续验证位置、滚动、多文件顺序和提示线。

不上传测试源码，不增加 Actions 测试步骤。
