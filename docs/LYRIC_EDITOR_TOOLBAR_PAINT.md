# 歌词编辑工具栏按钮残影修复（2026-09-23）

## 原因

原版 `FUN_0044CB58` 通过 `FUN_0042AE9B` 创建工具栏，样式为 `0x46018944`，
其中包含 `TBSTYLE_TRANSPARENT`。重建版保留了该样式。透明工具栏依赖父窗口
提供背景，按钮悬停、按下和恢复时不能只把新图标叠加到旧画面上。

waskin 原来对 `WM_ERASEBKGND` 直接返回 1，没有实际绘制背景；普通绘制又会裁掉
宿主管理的工具栏与 RichEdit 区域。因此工具栏无法擦掉上一状态的像素。
这是程序的背景绘制衔接问题。

## 修复

- `TTP_SKIN_CONTENT_CHILD` 属性增加明确角色：1 为不透明编辑框，2 为透明工具栏。
  原有非零值保护规则保持兼容，接口结构和 ABI 版本不变。
- 宿主将歌词工具栏标记为透明子控件，继续使用原版工具栏样式、按钮资源和命令。
- DLL 在视频窗口收到背景擦除消息时实际绘制；透明子控件提供的 DC 或主题内存 DC
  可取得工具栏下的背景。直接绘制父窗口的屏幕 DC 仍排除工具栏区域。
- 普通 `WM_PAINT`、`WM_PRINTCLIENT` 和导出的 `paint` 保持对子控件的裁剪，
  RichEdit 在背景擦除路径中也始终受保护，避免歌词覆盖正在编辑的文字。

## 验证方法

本地回归位于 `rebuild/tests/waskin/toolbar_paint_host_tests.inc`：

- 使用两种不同的旧像素填充画布，再让真实透明工具栏绘制；结果必须逐像素相同。
- 依次切换可见按钮的悬停、按下、释放和移出状态，恢复后的画面必须等于初始画面。
- 覆盖 508、320、620 像素窗口宽度，以及歌词和歌词／视觉同屏模式。
- 检查父窗口的正常绘制不会覆盖工具栏及 RichEdit；继续执行既有视频歌词回归。

修复需要配套更新 EXE 与 `AddIn/ttp_waskin.dll`；普通版和 XP／Win7 版共用同一 DLL。
测试代码仅保留本地，Actions 不运行测试。

本次验证结果：旧代码在“不同旧背景必须得到相同工具栏像素”的断言处失败；修复后，
普通版与 XP／Win7 版宿主均通过新增工具栏检查及既有视频歌词回归。DLL 资源解析、
控件和接口兼容回归通过。两版 Release 构建成功，DLL 的 XP／Win7 导入审计通过
（5 个系统 DLL、177 个导入），兼容版 EXE 为 19 个 DLL、655 个导入。
界面回归在当前 Windows 上执行，本次未重新运行 XP／Win7 虚拟机。
