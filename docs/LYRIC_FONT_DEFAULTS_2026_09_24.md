# WSZ / WAL 歌词默认字体与播放列表一致

## 原因

原来的 `lyric_font_height` 接口只返回 `-11`，主程序仅覆盖歌词字号，保留原生皮肤或上一款皮肤的字体名称、字重等属性。相同的 11 像素字号，在 Arial、Tahoma、宋体和微软雅黑中并不具有相同的实际字形和测量尺寸。

例如 `[ZnT]_Pink_hearts.wsz` 的 `pledit.txt` 指定 `Font=Tahoma`，内置 base-2.91 使用 Arial。歌词以前并未跟随这项选择。

## 修复

- 插件 ABI 尾部增加可选 `lyric_font` 查询，返回完整 `LOGFONTW`，不传递字体句柄或跨 DLL 分配的内存。
- WSZ 从实际播放列表 `HFONT` 取得默认字体，沿用现有 `Font` / `TextFont` 解析规则、11 像素字号及字重、字符集等属性。
- WAL 的内嵌播放列表和歌词默认字体由同一个 GDI+ 字体工厂提供。目前该播放列表使用 Tahoma、11 像素、常规字重；通过 `GetLogFontW` 转为原生歌词使用的 GDI 字体。此处并不取 XML 中其它文字控件使用的位图字体。
- 主程序先应用完整默认字体，再读取目标皮肤的已保存歌词字体。播放歌词、内嵌/独立歌词编辑器及“歌词秀”字体选择使用同一份设置。
- 用户在“歌词秀”单独修改后，仍按原有方式保存，重新选择皮肤或重启不会被播放列表默认字体覆盖。全屏歌词继续使用其独立字体设置。
- 旧插件没有新接口时，主程序继续使用原来的字号接口；新插件向旧主程序只写入调用方声明的 ABI 长度。

已有皮肤侧车 XML 中的 `Lyric Font` 仍视为已保存的设置。旧文件未记录该字体是否由用户手动选择，因此本次不猜测或清除它；没有保存字体、配置未指定字体或恢复皮肤默认值时，采用新的完整默认字体。

## 验证

本地 C++ 回归位于 `rebuild/tests/waskin`，不纳入发布包或 Actions：

- WSZ 完整字体描述、中英文与数字的实际 GDI 字体尺寸；`Font` / `TextFont` 指定的不同字体。
- 歌词编辑器、实际“歌词秀”字体选择、保存、重选皮肤和新程序实例恢复；全屏字号独立。
- HeadAMP WAL 的默认字体、自定义字体保存、恢复默认，以及内嵌和独立歌词编辑器。
- ABI 旧版和截断缓冲区保护；共用 DLL 的 XP / Win7 导入检查。

本次需要同时更新主程序和 `AddIn/ttp_waskin.dll`，`ttp_maki.dll` 无需更新。

验证结果：普通版和兼容版在本机的 WSZ / WAL 回归通过，Win7 虚拟机完整通过上述字体、编辑器及内容回归。XP 已输出默认字体及中英文尺寸检查通过；完整绘制回归耗时超过来宾命令等待时限，随后虚拟机状态变为暂停、关机，剩余检查未完成，不计为通过。未重新启动已关机的虚拟机。另提供本地 C++ `--lyric-font-only`（可同时指定 `--modern-only`）进行聚焦复测。
