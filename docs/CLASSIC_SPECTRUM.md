# Winamp 皮肤独立频谱与效果切换修复

日期：2026-09-20。

## 问题原因

此前 `Skin::Visual` 将全部效果交给千千的 `VisualRuntime::Paint`。即使传入 `viscolor.txt` 的部分颜色，频谱仍采用千千的三色插值、柱形和峰值算法，再缩放到 WSZ 的小区域，外观与 Winamp 经典频谱不同。

另一个问题发生在效果切换：`SetVisualType` 调用 `UpdateVisualWindowLayout`，无条件使用原生后备皮肤的 `visual` 元素位置和尺寸，并通过 `SWP_SHOWWINDOW` 显示原生子窗口。插件的 `HideChildren` 要等后续消息／100ms 定时器才隐藏它，因此短暂露出尺寸和位置不属于当前 WSZ 的图形。

## 实现

### DLL 内的频谱样式

[spectrum.cpp](../src/spectrum.cpp) 维护经典样式的柱高、峰值和速度；[visual.cpp](../src/visual.cpp) 将调色板索引绘制到当前皮肤的限定区域。

- 保留全部 24 个颜色项：0 是背景、1 是点阵、2…17 是频谱逐行颜色、23 是峰值；18…22 保留给示波器颜色。可用的部分调色板覆盖对应默认项，剩余项使用 Winamp 默认颜色。
- 使用 Winamp 默认的三列绘制、一列间隔；峰值不是千千的插值渐变。
- 动画按 16ms 步进：柱高下降量为 12/16，峰值初始速度为 3/256、加速度系数 1.1。重复重绘不额外加速，暂停冻结，停止／切换效果清除旧帧状态；长时间无绘制的单次追赶有上限。
- 分别处理正常、折叠、双倍尺寸。双倍折叠按原版输出 75 列及一列留白，不把 37 列直接拉宽。单倍正常模式保留原版底向上 DIB 的实际取图／裁剪结果。
- 加宽播放列表使用正常频谱左侧的 72 像素，修正此前位置偏移及 70 像素压缩；对应鼠标命中也同步修正。
- 所有绘制先限制裁剪区，保持皮肤窗口的背景与相邻控件不被覆盖。

本次匹配的是 **Winamp 默认经典频谱的样式和绘制行为**。没有增加 Winamp 自己的配置菜单、火焰／线条频谱模式，也没有更换千千音频引擎。频率取样和强度继续来自千千既有 FFT，再映射到 75 列，因此不声称对同一音频与 Winamp 的 FFT／输入缓冲产生完全相同的柱高。梦幻、波形和封面继续复用千千功能。

### 宿主提供分析快照

`TtpSkinHost.spectrum` 是 ABI v1 的可选尾部回调。`TtpSkinSpectrumFrame` 提供效果类型、播放状态、配置代数、帧序号及原生 FFT 的前 256 个幅值；由 `VisualRuntime` 在原有锁下复制，不在绘制回调内再次执行 FFT，也不直接访问解码缓冲区。

没有完整回调的旧宿主仍可加载 DLL，频谱回退到原有宿主绘制。`resize` 和更早的 `tip` 等回调继续按完整字段长度读取。完整修复需要配套更新 EXE 与 DLL；普通版、XP／Win7 版仍共用同一个 DLL。

### 消除切换时的错误尺寸图形

- 插件接管嵌入区域时，布局更新始终隐藏原生可视化子窗口，不再发出临时显示请求。
- 原有分析线程继续运行；通过原子标志选择刷新插件窗口，而不是取得隐藏子窗口的 DC 并绘制。
- `PaintVisualControl` 和停止时的背景清除也避开插件已接管的原生子窗口。
- 插件加载完成后立即刷新可视化配置；原生后备皮肤没有 `visual` 元素时，也保留离屏分析能力。
- 切回原生皮肤恢复原生子窗口。已脱离为全屏的可视化仍走既有全屏分支。

## 验证

测试仅保存在 `rebuild/tests/waskin`，未加入发布包或 Actions。

- `waskin_spectrum_tests`：384 帧与按 `draw_sa.cpp` 构建的底向上 DIB 参考逐像素一致，覆盖四种尺寸模式、柱形／峰值衰减、暂停、重绘、重置和计时器回绕。
- 实际 DLL：验证默认／完整／部分 `viscolor.txt`、逐行颜色、峰值、柱间隔、双倍尺寸边界、双倍折叠细柱、列表坐标和 72 像素裁剪。
- 原有 DLL 控件、资源、保护页 ABI 尾部及 30 次生命周期测试通过；Pink hearts 的短图集、标题和底部时间回归通过。
- 普通版与 XP／Win7 版分别通过定向宿主测试：每次 30 次效果切换，原生子窗口无显示请求；隐藏状态仍产生实际非零 FFT 幅值；切回原生再加载插件后重复检查通过。每版共检查 60 次切换。
- 完整宿主套件中的既有真实鼠标悬停用例两次受到外部前台／光标变化干扰，本轮未将其记为通过。上述定向测试不依赖前台鼠标，未削弱原套件的默认检查。
- 两版 Release 构建通过；DLL 静态导入审计为 5 个依赖 DLL、166 项导入，旧系统 EXE 为 19 个依赖 DLL、648 项导入。运行验证在当前 Windows 主机完成，不代替 XP／Win7 真机验证。
