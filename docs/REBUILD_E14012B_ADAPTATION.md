## 本次修正

### 音量

旧插件使用 `delta / 120 * 5`，现在与原生主窗口一致使用 `delta / 40`：标准一格改变 3，40 改变 1，余数不跨消息累计。连续滚轮发送相对增量，由 UI 线程按顺序应用，避免多条消息都根据旧快照计算绝对音量。

绝对滑块和相对滚轮统一调用主程序的音量方法。静音时可修改保存音量，输出仍为零；插件状态仍显示保存音量，不再把滑块误归零。

主程序直接查询插件是否正在捕获音量滑块。拖动期间，滚轮/快捷键不覆盖滑块位置，提示不被超时清除；松开、取消或失去捕获时结束提示。WAL 同时识别 XML 音量滑块及通过 MAKI setVolume 驱动的鼠标手势。

WSZ 主标题区、WAL 中声明了 songname/songtitle/songinfo 的文字控件读取主程序本地化提示；非 ASCII 文本使用字体绘制，以免中文落入只含 ASCII 的位图字库后消失。WAL 脚本明确设置的 alternatetext 保留其优先级。

### 查找和选择

原生查找只让隐藏的原生列表滚动，插件列表仍停在旧位置。本次在 `EnsurePlaylistSelectionVisible` 和原生列表的 `LVM_ENSUREVISIBLE` 中通知插件。

接口分别传递待显示行和键盘当前行。快速查找选中所有匹配项、滚动到第一项，同时保留最后一项为当前行；Enter 仍播放当前行。回调只同步滚动及当前行，不发送新的选择命令、不打开隐藏窗口。WAL 在嵌入列表下一次布局绘制时应用滚动，使抽屉尚未展开时也能保留待显示行。

### 主窗口消息

WSZ 以前吞掉所有 `WM_SIZE`，主程序无法执行托盘恢复、桌面歌词重新显示和任务栏预览刷新。本次仅让主窗口继续进入宿主消息处理；播放列表、均衡器、视频等辅助窗口尺寸仍由插件维护。

### 全屏与托盘最小化

回归发现 `c86ad1a` 的托盘逻辑会取消全屏：`SetFullScreenMode` 先设置全屏模式，再最小化主窗口；`SC_MINIMIZE` 进入 `MinimizeToTray`，后者又调用 `LeaveFullScreen`。因此默认启用托盘最小化时，WSZ 视频和 WAL InlineAVS 都无法进入全屏。

本次让 `WM_SYSCOMMAND` 和 `WM_SIZE` 的托盘分支仅在非全屏模式触发。全屏内部仍最小化并隐藏主窗口，完成原生歌词/视觉窗口的全屏布局。普通最小化、关闭隐藏和退出全屏后的托盘功能保留。

## ABI 与兼容

- 现有命令编号保持不变，在 `TTP_SKIN_EQ_VALUE = 100` 前增加音量相对增量、手势结束、状态文字查询三个编号。
- 在 `TtpSkinPlugin` 尾部追加可选 `volume_tracking` 和 `playlist_reveal`，按调用方提供的结构长度复制，旧宿主/旧 DLL 不越界。
- 新宿主通过 `host.option(TTP_SKIN_VOLUME_DELTA)` 声明支持；旧宿主回退到原有绝对音量命令，不发送未知的结束命令。
- 两份公开 SDK 头文件保持一致。新增行为需同时更新主程序和 `AddIn/ttp_waskin.dll` 才完整生效。
- 不依赖 Wasabi，不修改 MAKI VM，不引入新的高版本 Windows 导入。
